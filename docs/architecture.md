# System Architecture

## 1. Overview

The project is an inline SCADA deception and intrusion-prevention system.

An external client/attacker interacts with a Digital Twin that emulates the first relevant stage of the SWaT process.

The Digital Twin safely absorbs attacker interaction while producing realistic cyber-physical responses.

Telemetry generated by the Digital Twin is analyzed by:

- Anomaly Detection
- Signature Extraction Module (SEM)

SEM produces a candidate signature and rule.

The system waits for Anomaly Detection.

If anomalous, the generated rule is deployed to Snort IPS on pfSense.

If normal, the candidate rule is discarded and permitted traffic is forwarded to Main SCADA.

# 3. Digital Twin

The Digital Twin is an inline SCADA honeypot.

It accepts Modbus TCP traffic and simulates the consequences of commands.

Example:

Client:
    Open inlet valve

Digital Twin:
    valve state changes
    flow changes
    tank level changes
    sensor response changes

The attacker receives a believable SCADA response.

The simulated plant is isolated from the real physical Stage 1.

---

# 4. State Manager

The State Manager is the authoritative owner of Digital Twin state.

Responsibilities:

- current state
- previous state
- actuator states
- sensor states
- timestamps
- state version
- physical Stage 1 synchronization

It does not implement physical equations.

---

# 5. Physical Stage 1

The physical Stage 1 is the reference plant.

The Digital Twin periodically reads state from the physical Stage 1.

Direction:

Physical Stage 1 -> Digital Twin

Never:

Digital Twin -> Physical Stage 1

Attacker commands must never reach the physical plant.

---

# 6. Physics Engine

The Physics Engine provides deterministic process behavior.

It models:

- flow
- tank levels
- actuators
- pumps
- valves
- sensor relationships
- physical constraints

It is the sole simulation engine for the Digital Twin.

---

# 7. Telemetry

Telemetry contains:

- network information
- Modbus information
- process/sensor state
- actuator state
- previous state
- state changes
- derived network statistics

Telemetry is the contract between the Digital Twin and the detection system.

---

# 9. Detection

Anomaly Detection and SEM execute concurrently.

Anomaly Detection determines whether behavior is anomalous.

SEM extracts a candidate behavioral signature.

Rule Generator converts the candidate signature into a candidate Snort rule.

---

# 10. Enforcement

If Anomaly Detection returns NORMAL:

    discard candidate signature/rule
    permit/forward traffic

If Anomaly Detection returns ANOMALY:

    accept candidate signature
    deploy candidate Snort rule
    block the malicious transaction
    protect against subsequent matching traffic

---

# 11. Important Security Property

The packet that causes an anomaly is processed by the Digital Twin.

It is never forwarded to Main SCADA after being classified as malicious.

Subsequent matching packets can be blocked earlier by Snort.
